# 骑行页面 Spotify 播放器设计

## 目标

在骑行主页顶部导航加入一个音乐按钮。访客点击后展开 Spotify 官方歌单播放器；播放器不自动播放，不遮挡地图的缩放、全屏等控制，并适配浅色、深色和手机布局。

## 已确认方案

- 音源使用 Spotify 歌单 `1r8NqobH79G9YEA3Iobx4a`。
- 音乐按钮放在 `About` 与主题按钮之间，尺寸与主题按钮一致。
- 桌面端播放器从导航栏右侧向下展开，采用紧凑卡片，不常驻占用地图空间。
- 手机端采用接近全宽的浮层卡片，并保留安全边距。
- iframe 始终保持挂载；收起仅隐藏外层，因此已经开始的播放可以继续。
- 默认关闭且不自动播放。点击按钮切换展开/收起，按 `Escape` 或点击播放器外部可收起。

## 组件与数据流

新增 `MusicPlayer` 组件并由 `Header` 渲染。组件内部只维护展开状态，不接触骑行活动数据。

1. 用户点击导航栏音乐按钮。
2. `MusicPlayer` 切换展开状态，并更新 `aria-expanded`。
3. 展开面板显示 Spotify 原生 iframe，地址为：
   `https://open.spotify.com/embed/playlist/1r8NqobH79G9YEA3Iobx4a`
4. 收起时不销毁 iframe，避免主动中断已经开始的播放。

## 视觉与响应式规则

- 外层沿用当前页面的米白、深蓝、边框和阴影变量。
- 播放器容器圆角约 18px，iframe 使用 Spotify 自带圆角。
- 桌面端宽度约 380px，紧凑高度约 152px，定位在音乐按钮下方。
- 手机端宽度为视口减去两侧 12px，最大宽度仍受桌面尺寸约束。
- 面板层级高于页面内容，但只在展开时接收点击，地图控件保持可用。

## 可访问性与失败处理

- 按钮提供中英文可理解的 `aria-label`、`aria-expanded` 和 `aria-controls`。
- 面板具有可识别标题，并支持键盘 `Escape` 收起。
- iframe 提供 `title`，保留 Spotify 官方控件与权限声明。
- 面板内提供“在 Spotify 中打开”链接；即使 iframe 因网络或地区限制不可用，访客仍可打开原始歌单。

## 验证

- 先添加一个会失败的组件契约测试，验证音乐按钮、Spotify 地址、默认收起状态和回退链接。
- 运行格式检查、代码检查和生产构建。
- 在本地页面验证：打开、收起、点击外部、`Escape`、浅色/深色以及窄屏布局。
- 推送后检查 GitHub Pages 线上页面，确认播放器显示和交互正常。
